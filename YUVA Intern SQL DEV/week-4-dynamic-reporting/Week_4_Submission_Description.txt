Week 4 Submission Description – Dynamic Reporting and Data Visualization Using SQL

This submission presents a reproducible SQL reporting solution for the virtual retail environment developed during the earlier weeks of the SQL Developer Internship. Week 1 established the relational retail model, including customers, categories, products, suppliers, warehouses, inventory, orders, order items, payments and shipments. Week 2 documented the ETL workflow and data-quality controls. Week 3 addressed SQL query optimization, execution-plan analysis and the benefits and costs of indexes. Week 4 builds the reporting layer on those foundations.

The report answers eight business questions: top products by delivered revenue, category performance, monthly delivered-sales trends, highest-value customers, repeat-customer rate, low-stock products by warehouse, estimated stock-cover days, and order-status distribution. The SQL uses joins, CTEs, aggregations, conditional expressions, subqueries and window functions. Each analysis defines its metric, explains the query logic, interprets the output, recommends a suitable visualization, and identifies the business action and limitations.

The package includes PostgreSQL-targeted SQL scripts, a deterministic synthetic dataset, exact query-result CSV/Markdown files, dataset row counts, validation evidence, chart examples, and the detailed DOCX report. The synthetic dataset is generated with a fixed seed and contains no real customer information. All eight reporting query logics were executed automatically against a local SQLite verification mirror and the validation checks passed. The build environment did not provide a PostgreSQL server, so the submission does not claim that PostgreSQL execution plans or performance benchmarks were captured. PostgreSQL-specific execution and EXPLAIN (ANALYZE, BUFFERS) remain the next validation step in the target database.

The report also addresses the prior evaluation feedback by explaining why each reporting and optimization technique is used, its expected benefit, and its trade-offs. It distinguishes delivered merchandise revenue from net revenue, identifies why true inventory turnover cannot be calculated without dated stock movements and cost data, and proposes future improvements such as returns/refunds tracking, warehouse-level demand attribution, customer cohort retention, governed materialized views, currency handling and measured dashboard performance.

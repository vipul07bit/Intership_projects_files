Week 3 Submission Description - SQL Query Optimization and Performance Tuning

This submission applies SQL query optimization and performance tuning to a virtual retail database in PostgreSQL. It continues Week 1, where the retail data model was designed, and Week 2, where the ETL plan was written. The lab schema holds 870,500 synthetic rows: 500 suppliers, 50,000 customers, 10,000 products, 200,000 orders, 600,000 order items and 10,000 inventory records. Counts were verified with COUNT(*) after running the supplied scripts.

I analysed seven retail queries: customer order history, product category browsing, delivered sales for a year, a customer-order join, low-stock inventory, a year filter written with DATE_PART, and monthly delivered revenue. The techniques were composite and covering indexes, a partial index, a sargable date-range rewrite, a narrower column list instead of SELECT *, and range partitioning of orders by date. Each query is documented with its business problem, original SQL, optimized SQL, plan evidence, trade-offs and a retail use case.

Results use EXPLAIN (ANALYZE, BUFFERS), one discarded warm-up run and the median of five runs. In the reproduction run on PostgreSQL 16.15, customer order history fell from 11.073 ms to 0.014 ms (99.9%), the customer-order join from 11.856 ms to 0.051 ms (99.6%), monthly delivered revenue from 20.462 ms to 6.742 ms (67.1%, Index Only Scan), and a full-year date report from 25.401 ms to 12.603 ms with partition pruning (50.4%). Some changes did not help: the low-stock partial index was inconclusive on a 10,000-row table and the DATE_PART rewrite alone was not significant. These are reported honestly.

I also interpreted my own four execution plans. The cost 10000000000.00 shows that sequential scans were disabled, the estimate of 1,000 rows against 53,673 actual rows comes from a function applied to a column, and partition pruning was confirmed in the plan for orders_p_2026. Index size, write cost, limitations and reproducibility steps are included, along with the CSV, SQL scripts, benchmark protocol, flowchart and README.
